# 문제 본문 표시

CSV의 문제·보기·정답과 문항 ID는 그대로 보관하고, 화면 출력 시 질문·상황/자료·보기·조건을 구분한다. 표시 변경으로 풀이 기록이나 숙련도를 초기화하지 않는다.

- 질문 앞의 독립된 설명 문장은 상황·자료로 표시한다.
- ㄱ. / ㄱ: / (ㄱ), A. / A: 등의 연속된 항목을 보기 상자로 표시한다. 각 항목은 한 줄씩 구분한다.
- 빈칸 참조 `(ㄱ)이라`, `(ㄱ)과`는 보기로 분리하지 않는다.
- 보기 뒤의 공통 조건, 판례 기준, 계산 제한 등은 별도 조건 영역으로 표시한다.
- 기존 `[CONTEXT]`, `[TABLE]`, `[QUESTION]` 등의 구조도 지원한다. 표의 줄바꿈과 구조 밖의 문장도 보존한다.
- 질문·보기·조건의 순서를 유지하며, 원문에 없는 정답 단서를 추가하지 않는다.
- 개별 문항의 원문에 항목 구분용 `/`가 있으면 보기 상자 안에서만 숨긴다.

풀이·모의고사·맛보기·해설 열람·문제별 결과 화면은 같은 표시 컴포넌트를 사용한다. 목록의 짧은 제목은 기존 요약 표시를 유지한다.

## 전체 점검

현재 카탈로그 1,400문항의 원문 보존 검사를 통과했다. 유형별 중복 집계로 보기 포함 59문항, 조건 포함 140문항, 상황·자료 포함 507문항이다. 이는 문항 내용의 정오 검수와는 별개인 표시 구조 검사다.

CSV를 추가·수정한 뒤 다음 명령으로 DB에 반영된 모든 문항의 구조를 확인할 수 있다.

```sh
python manage.py audit_question_layouts --output /tmp/question-layout-audit.json
```

보고서에는 문항 ID별 분리 결과가 담긴다. 이 명령은 데이터를 수정하지 않는다. 구분이 어려운 새로운 문장 형식은 원문을 보존해 표시하므로, 보고서를 확인해 표시 규칙이나 CSV의 명시적 구조 태그를 보완한다.
