# CSV 문제 추가·수정 안내

운영 원본은 `generated/logistics/`(물류관리사), `generated/realtor/`(공인중개사)의 CSV입니다. 하위 폴더와 `.CSV` 확장자도 지원합니다. `active/`, `archive/`, `generated/` 바로 아래 파일은 자동 운영 반영 대상이 아닙니다.

## 매번 할 일

1. 기존 CSV를 수정하거나 `docs/templates/questions.csv`를 복사해 새 문제를 작성합니다.
2. CSV UTF-8로 저장합니다. 엑셀에서는 **CSV UTF-8(쉼표로 분리)**을 선택합니다. 쉼표나 줄바꿈은 엑셀/CSV 편집기가 따옴표로 처리하도록 합니다.
3. GitHub에 저장합니다. Actions의 `Validate question CSVs`에서 파일·행별 오류를 확인합니다.
4. 정상 자료는 Render 자동 배포에서 검증 후 반영됩니다. 최종 완료는 Render의 **Live**와 로그의 `Catalog sync complete`로 확인합니다. Actions만 성공했다고 운영 반영이 끝난 것은 아닙니다.

잘못된 CSV는 신규 배포의 검증 단계에서 차단됩니다. 이미 서비스 중인 정상 배포는 계속 동작하고, 내용 변경은 전체 취소됩니다. 오류를 고쳐 다시 올리세요. 서버 시작 시 일부 파일만 성공한 상태로 넘어가지 않습니다.

## 열 작성 규칙

| 열 | 작성 방법 |
|---|---|
| 문항ID | 수정·이동해도 바꾸지 않습니다. 영문/숫자/하이픈/밑줄/점, 100자 이하. 전체 파일에서 유일해야 하며 대소문자를 구분하므로 대문자 사용을 권장합니다. |
| 번호 | 해당 파일에서 중복되지 않는 양의 정수. CSV 줄 번호가 아닙니다. 기존 번호는 되도록 유지하세요. |
| 과목·챕터 | 기존 CSV의 과목명과 챕터 코드를 참고합니다. 두 값이 일치해야 합니다. `챕터` 대신 기존 파일의 `분류코드` 열도 지원합니다. |
| 난이도 | 하 / 중 / 상 |
| 문제·보기1~5·정답·해설 | 모두 작성합니다. 정답은 1~5의 숫자입니다. |
| 문제이미지 | 없으면 빈칸. 있으면 `images/questions/.../q005.png`처럼 실제 GitHub 파일의 정적 경로를 입력합니다. 기존 `이미지` 열도 사용할 수 있습니다. 이미지 파일도 함께 올려야 합니다. 기존 그림을 제거하려면 `없음`을 입력하세요. 그림 내용을 수정할 때는 새 파일명으로 저장하고 CSV 경로도 변경하세요. 새 경로로 변경하거나 그림을 제거하면 이전 평가에서 제외하고 다시 확인하도록 합니다. |
| 사용여부 | `사용` 또는 `중지`. 기본은 사용입니다. |
| 수정유형 | 일반 수정은 빈칸. **뜻이나 조건을 바꾸지 않는 단순 오타**일 때만 `오타`를 입력합니다. 다음에 실제 문제 내용을 바꿀 때는 반드시 빈칸으로 되돌리세요. |

기존 모든 문항ID는 이전 DB의 ID 그대로 CSV에 기입되어 있습니다. 기존 ID를 새 규칙으로 바꾸거나 다른 문제에 재사용하지 마세요.

신규 ID 예시: `LOG-030-1-005`(물류 30회 1교시 5번), `REA-037-1-005`(공인중개사). 중간에 새 문제를 넣을 때 기존 ID를 밀지 말고 `LOG-030-1-005-A`처럼 새 ID를 부여하고, 번호 열에는 그 파일에서 사용하지 않은 숫자를 사용하세요. 완전히 다른 문제로 교체할 때도 새 ID를 사용합니다.

## 수정에 따른 학습 기록

- 같은 ID: 기존 문제를 갱신합니다. 파일명/폴더/챕터/배열 순서가 바뀌어도 새 문제를 만들지 않습니다.
- 해설만 보완하거나 `오타`로 수정: 기존 풀이 기록을 유지합니다.
- 문제 조건·보기 변경(수정유형 빈칸): 예전 풀이를 보존하되 현재 평가에서 제외하고 다시 확인하도록 합니다. 최근 해설 열람/아는 내용 표시도 해제합니다.
- 정답 변경: 수정유형이 `오타`여도 예전 채점은 현재 평가에서 제외합니다.
- `중지`: 재출제하지 않고 기록은 보존합니다. 다시 `사용`으로 바꾸면 재개됩니다. 다만 별도의 검수 보류 문항은 재검수를 거쳐야 합니다.
- 행/파일 삭제: DB에서 자동 삭제하거나 중지하지 않습니다. 누락 ID 경고가 나옵니다. 실제 중단하려면 해당 ID의 행을 복원하고 `중지`로 올리세요.

수험생에게 관리용 ID나 전체 보유 문제 수는 표시하지 않습니다. 기존 기록이 유효하지 않게 된 문제에는 수정 안내를 표시합니다.

## 운영자 검증·반영 명령

```bash
python manage.py validate_mission_csvs
python manage.py sync_content_catalog --dry-run
python manage.py sync_content_catalog
```

전체 파일을 강제로 다시 반영할 때는 `--force`를 사용합니다. 기본은 변경 파일만 처리합니다. 이미지·검수 자료·동기화 로직 변경도 재반영 조건에 포함됩니다. 새 DB는 전체를 반영합니다.

`추가/수정/중지 문항ID`, 파일별 반영 결과, 과거 채점 제외 건수는 Render 로그에서 확인합니다. 변경 없는 CSV는 `UNCHANGED`로 표시됩니다. 이 상세 정보는 수험생 화면에는 나오지 않습니다.


## 모의고사 응시 중 수정

새 시험은 시작할 때의 문제·보기·정답·해설을 고정해 응시 중 CSV 교체의 영향을 받지 않습니다. 의미나 정답이 바뀌면 과거 시험 점수는 유지하고 옛 답안은 현재 학습 통계에서 제외합니다. `오타` 수정은 기존 유효성을 유지합니다. 기존 완료 시험에 원문 정보가 없는 경우에는 소급 복원할 수 없습니다.

과거 시험의 이미지 경로를 보존하므로 이미지 변경 시에는 새 파일명으로 추가하고 기존 파일을 유지하세요. 같은 경로의 파일을 덮어쓰거나 삭제하면 과거 이미지를 복원할 수 없습니다.
